# 草稿生成核心

依系統架構的「草稿生成」規格，提供初次邀約（`initial_invitation`）與追蹤
（`follow_up`）公版的純文字替換。依本次確認，公版由使用者自行貼入、編輯；
第一版只完成生成核心，頁面等資料庫接好再做。

## 使用方式

以下內容與欄位都是虛構示例，不是內建公版：

```ts
import { generateDraft, inspectDraftTemplate } from "./index.ts";

const template = {
  kind: "initial_invitation",
  subject: "{{活動名稱}}合作邀約｜{{廠商名稱}}",
  body: "{{聯絡窗口}}您好：\n我們將於{{活動日期}}舉辦{{活動名稱}}，希望洽談{{合作需求}}。",
} as const;

const inspection = inspectDraftTemplate(template);
// 成功時 requiredFields 依主旨、內文首次出現的順序列出欄位，不重複。

const result = generateDraft(template, {
  活動名稱: "示範社團成果展",
  廠商名稱: "示範文具公司",
  聯絡窗口: "示範窗口",
  活動日期: "2026-12-20",
  合作需求: "活動用品贊助",
});

if (result.ok) {
  // result.draft.subject / body 是可供後續編輯的純文字。
  // status 永遠是 draft，perMessageApproval 永遠是 not_approved。
} else {
  // 顯示 result.issues，缺資料時用 field 找出要補的欄位。
  // 不回傳部分草稿。
}
```

## 公版與資料規則

- 語法為 `{{欄位名稱}}`，括號內名稱前後可有空白；名稱區分大小寫，
  支援中文字、英文字、數字及底線，不能以數字開頭。不支援運算、路徑、條件或巢狀公版。
- 主旨與內文必須非空白。雙大括號缺漏、空欄名或不支援的語法都會回報，
  不默默留下未填欄位。沒有欄位的純文字公版也可使用。
- 必填欄位以公版實際引用者為準；資料須是物件本身的字串值，
  缺少、`undefined` 或純空白時回報缺資料，其餘型別回報格式錯誤。
  不讀取繼承屬性或執行 getter；未引用的資料忽略。
- 保留公版及資料的原始文字與內文換行。每個欄位只替換一次流程，
  資料中的 `{{...}}`、`$&` 等符號保持原文，不再次解析或執行。
- 主旨在替換前後都不能換行；內文可以換行。輸出是純文字，呼叫端不可直接當 HTML 插入。
- `issues` 只包含代碼、位置、必要的欄位名稱及固定訊息，不附上完整公版、信件或欄位值。
  欄位名稱仍來自使用者輸入，呼叫端不要直接將整個結果寫入錯誤紀錄。

## 範圍與後續串接

這是沒有副作用的函式：不讀取環境變數、不呼叫 AI 或 Google、不保存公版或草稿。
`kind` 只表示採用哪種公版，不判斷廠商是否符合追蹤條件；相關規則仍由 `lib/rules` 處理。

本次尚未接上資料庫、網頁、寄前檢核、審核佇列或 Gmail。生成成功只代表公版資料填齊，
不代表資料已核實、連結可存取、附件正確或可以寄送。未來呼叫端須先驗證身分、社團與資料權限，
再從可信的資料存取層帶入已確認的廠商、窗口、活動日期及合作需求。

輸出不攜帶收件人、附件或核准憑證，不能代替 `lib/pre-send` 的結構化檢核結果。
之後接上寄信流程時，仍須逐封檢視收件人、主旨、內容、附件及版本，
記錄核准人、時間與版本；任何修改都須重新審核。舊資料暫存流程維持本次先暫緩的範圍。

測試全部使用虛構資料，離線執行，不載入 `.env.local`、不花 AI 費用。
